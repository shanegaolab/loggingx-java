# 日志备份（归档）

日志库里的日志是**热数据**：放在 ClickHouse 里，用于日常查询、实时日志和告警排查，按日志库的「保留天数」删除，保持查询快、磁盘可控。**备份**把较早的日志按天压缩，存到 S3 兼容对象存储（**冷数据**），成本低、保留久，需要时恢复回日志库查询。两者是分层关系：

| | 日志库（热） | 备份（冷） |
| --- | --- | --- |
| 保留 | 保留天数，通常 7~30 天 | 归档保留天数，通常 180 天~数年 |
| 存储 | 本地磁盘（ClickHouse） | MinIO、阿里云 OSS、腾讯云 COS、AWS S3 等 |
| 查询 | 直接查询 | 恢复到日志库后查询，或下载后离线查看 |

一级菜单「备份管理」是一个目录，分成两个页面，每个页面单独授权（权限标识即路由名）：

| 页面 | 路由名 | 用途 |
| --- | --- | --- |
| 归档策略 | `LogBackup` | 备份存储、每天的归档任务（可立即归档），以及各日志库的归档时机与保留天数 |
| 归档记录 | `BackupArchive` | 每个日志库每天一份归档，下载或恢复到日志库查看 |

日志库卡片上也能看到每个日志库的归档状态，并在新建或编辑日志库时一起设置归档。早期版本只有一个备份管理页面，升级后它会成为「归档策略」页面（菜单 id 不变），原来拥有它的角色自动获得「归档记录」。

## 存储

只支持 S3 兼容对象存储（AWS Signature V4）。在备份管理中配置服务地址、区域、存储桶、路径前缀和访问密钥，可以先「测试连接」（访问存储桶，写入并删除一个测试对象）再保存。

| 服务 | 服务地址 | 区域 | 寻址方式 |
| --- | --- | --- | --- |
| MinIO | `http://minio:9000` | `us-east-1` | 路径风格 |
| 阿里云 OSS | `https://oss-cn-hangzhou.aliyuncs.com` | `cn-hangzhou` | 虚拟主机 |
| 腾讯云 COS | `https://cos.ap-guangzhou.myqcloud.com` | `ap-guangzhou` | 虚拟主机（存储桶名带 APPID） |
| AWS S3 | `https://s3.us-east-1.amazonaws.com` | `us-east-1` | 虚拟主机 |

- 存储桶要事先创建。建议使用只能访问这个存储桶的子账号密钥。
- Secret Key 用 AES-GCM 加密后保存，接口不会返回明文。加密密钥由 `LOGGINGX_BACKUP_SECRET` 派生（默认等于 JWT 密钥）；改了它之后需要在页面上重新填写 Secret Key。
- 可在存储桶上配置生命周期规则，把较老的归档转为低频或归档存储，进一步降低成本。

## 归档

- **策略**：每个日志库可以开启归档，设置「超过 N 天归档」和「归档保留 M 天」。N 必须小于日志库的保留天数，保证每天的日志在删除前已经归档。
- **执行**：每天 02:30（`LOGGINGX_BACKUP_CRON`），在日志保留清理（03:30）之前运行，也可以在页面上「立即归档」。按日志库和天（服务器时区）打包：`<前缀>/<日志库编码>/yyyy/MM/dd.ndjson.gz`，没有日志的日期跳过。
- **格式**：gzip 压缩的 JSON Lines，每行一条日志，按时间顺序排列，日志文本通常压缩到 1/10~1/15，不依赖 LoggingX 也能直接查看：

  ```bash
  zcat order-service-2026-10-20.ndjson.gz | head
  zcat order-service-2026-10-20.ndjson.gz | jq -r 'select(.level == "ERROR") | .message'
  ```

  ```json
  {"id":"…","time":"2026-10-20T08:00:00.123456Z","seq":0,"level":"ERROR","host":"web-1","source":"/var/log/app.log","traceId":"…","message":"…","fields":{…},"receivedAt":"…"}
  ```

- **校验**：每个文件记录条数、压缩前后大小和 SHA-256；上传时把 SHA-256 作为签名的内容摘要，存储服务端会校验收到的内容。
- **失败重试**：上传失败的日期标记为失败，下次运行重试。
- **清理**：超过归档保留天数的归档从存储和清单中删除。正在恢复使用中的归档会等恢复到期后再删。
- 一天只归档一次，之后才到达的这一天的日志不会补进归档。

## 先归档、再删除

开启归档的日志库，删除日志前必须先归档成功：

- 每天的保留清理会跳过**已超过保留期但还没归档成功**的日期（归档失败、存储不可用、还没配置存储），等之后归档成功了再删。日志库卡片上会提示「N 天已超过保留期，归档成功前暂不删除」。
- 最多多保留 30 天：ClickHouse 写入的行级 TTL 是「保留天数 + 30 天」，作为兜底，精确的删除由每天的清理任务完成。
- 开启归档时，日志库的保留天数不能调到小于等于归档时机，否则会直接提示；暂停归档后不受此限制。

没有开启归档的日志库仍按保留天数直接删除。

## 恢复与下载

- **恢复**：把某天的归档写回原日志库（保留原日志 ID），在日志查询中按日期查看。恢复的日志保留 7 天，期间保留清理不会删除它们，之后自动清理（归档文件不受影响，可以再次恢复）。这一天的日志还在日志库中时不能恢复，直接查询即可。恢复失败会清除已写入的部分，可以重试。
- **下载**：生成 10 分钟有效的签名链接，浏览器直接下载 `.ndjson.gz`，存储不需要对浏览器开放。

## 日志库联动

| 操作 | 效果 |
| --- | --- |
| 新建 / 编辑日志库 | 在同一个弹窗里设置保留天数和归档（开启、时机、保留），两者冲突时会直接提示 |
| 日志库卡片 | 显示归档状态（已归档天数和大小），以及失败、待归档提醒，可一键进入备份管理 |
| 删除日志库 | 提示该库有多少天的归档；默认保留归档，仍可在备份管理中下载；也可勾选同时删除 |

## 配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LOGGINGX_BACKUP_CRON` | `0 30 2 * * *` | 归档任务的执行时间（秒 分 时 日 月 周） |
| `LOGGINGX_BACKUP_SECRET` | JWT 密钥 | 加密 Secret Key、签名下载链接的密钥 |
